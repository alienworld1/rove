`labScenarioSchema` and `labEventSchema` in `packages/contracts/src/lab.ts` define the input; `compileLabScenario` in `packages/lab/src/index.ts` validates semantics. Shapes below are generated from current Zod contracts and the fixture is checked by the real compiler.

## Fields and units

`schemaVersion` is exactly 1. Required top-level fields are `id`, `name`, `description`, `traceEpoch`, `corridor`, `lanes`, `events`, and `terminalCondition: "after_recovery"`. All objects are strict. There are 1–3 Lanes and 1–200 input events. Lane `maxPowerWatts` and `initialEnergyWh` are decimal integer strings; event readings use `cumulativeMilliWh`, not money or decimal kWh numbers.

Each event has `id`, `laneKey`, `traceOffsetMs` (0–3600000), unique `sequence` (0–10000), `type`, `parameters`, and nullable `durationMs`. Events order by offset, sequence, then ID; Lane order is normalized before hashing. The digest binds normalized definition and compiler version. Wall-clock playback speed does not change trace timestamps or the compiled digest.

The compiler checks approved meter profiles, unique Lane/session/meter/charger identities, valid Lane references, a preceding session start, nonregressing energy within each power/time bound, appropriate fault durations/restore events, and recovery after a fault. A shape-valid JSON object may still fail these checks.
