Public documentation and published recorded examples require no sign-in. An invite opens a private workspace for simulated charging scenarios with real Tempo testnet payments. A separate local development mode uses a local access key and simulated payments.

These are evaluation and integration workflows. They do not provide enterprise identity management, production partner authorization, certified meter key management, or physical charger control. Drivers do not use this interface.

## Access and secrets

In hosted mode, an invite establishes an HttpOnly session cookie. Private scenarios, runs, and controls require workspace ownership and the relevant permission. Access can expire or be revoked; starting runs also requires available run, funding, and fee allowances. Published recordings remain readable after access ends.

Local operational routes require development mode and a matching bearer secret; the browser gate establishes an HttpOnly local-session cookie. The local access key is at least 48 hexadecimal characters. Keep access keys, payer/payee/signer private keys, private RPC URLs, and database credentials in ignored local settings or appropriate secret storage. Never paste them into documentation links, snippets, search data, screenshots, or logs.

Only `NEXT_PUBLIC_DOCS_ORIGIN` and `NEXT_PUBLIC_APP_ORIGIN` belong in cross-application navigation configuration. They must be HTTP(S) origins without credentials, paths, queries, or fragments. Deployed builds require explicit origins. Public links include no run/Lane/event payload or return redirect. The original product tab preserves inspection state.

## Validation and source authority

Strict schemas, body bounds, path/body identity checks, command idempotency, optimistic versions, evidence hash/sequence/time continuity, and monotonic voucher limits protect the current boundaries. Browser mutations require a matching Origin. These defenses do not replace production transport authentication, partner-scoped authorization, key rotation, rate controls, or a complete access audit.

Authenticate meter session binding and key provenance; an allow-listed example key is not certification. Keep signer authority server-side. Current chain observations and canonical receipts establish money outcomes; database projections and submitted hashes cannot establish new funding. Browser consumers receive sanitized projections rather than raw operational secrets.

## Physical and accounting limitations

Rove emits a pause requirement. Your CPMS must enforce it on a physical charger. Controlled twin enforcement is not production OCPP control. Accounting supports immutable energy-only tax-free records with explicit currency/asset equivalence, not invoices, FX, refunds to drivers, or generalized OCPI conformance.
